Scheduling Poisson Machine for Adaptive Crawling

Intelligent data acquisition (crawl period optimization) combining statistical page-change detection and machine learning

Overview Poisson-process-based adaptive crawl manager

A smart crawler manager built on a Poisson process and ML

  • Project context: Dynamically optimize the crawl period by tying it to how fast stock changes on shopping-mall product pages. Suppressing redundant crawls minimizes waste of in-house collection infrastructure, and not missing stock-change moments yields accurate market demand estimates.
  • Core mission
    • Analyze the limits and inefficiency of the existing fixed-period (score-based) crawler (As-Is vs To-Be)
    • Define the target variable for applying the page-change model (Poisson process) and validate it by simulation
    • Clean outliers in raw unstructured collection data, engineer features from EDA, and build the pipeline
    • Build a period-control engine that combines a statistical model (Poisson) with an ML classification model

Problem Definition Infrastructure load and data gaps from fixed-interval crawling

Limits of fixed-period collection: a vicious cycle of wasted infrastructure and lost business opportunity

  • As-Is: Over-crawling (resource inefficiency) — Static pages with almost no stock change (unpopular products, etc.) were crawled mechanically and often, driving up networking resources and processing storage cost.
  • As-Is: Under-crawling (data loss) — Fast-selling hot-deal pages were not collected in time, so the precision of demand-change estimates stalled. Per-platform traffic thresholds (Lotte, Hmall, GS, 11st, Coupang, G-market, SSG, etc.) were also not reflected.

Theoretical Modeling Finding the optimal crawl period with a Poisson process

Modeling dynamic web page change detection with the Poisson process

Theoretical background (Cho & Garcia-Molina, 1999)

\[P(N(t)=k) = \frac{(\lambda t)^k e^{-\lambda t}}{k!}\]

Based on the theory that page-change intervals are independent and follow an exponential distribution.

Breaking through practical limits — The classic Poisson change rate (\(\lambda\)) is a fixed constant, so it cannot predict the varying cycle of each product. Instead, I collected change/no-change data per time unit (0.2H, 0.5H, 1H, 4H, 8H, 12H, 24H, 48H, etc.), simulated a local \(\lambda\) and change probability for each interval, and turned the interval with the maximum probability into the target variable.

Target Variable Engineering Validating the target variable by Excel simulation

Target variable simulation and validation of data cleansing (preprocessing)

  1. Window slicing and quantification: From the current time, sampled change/no-change data per time unit, such as 4H (last 24 hours) and 12H (last 72 hours), aggregated it, and computed \(\lambda\).
  2. Target labeling and tie-breaking: The interval with the highest change probability becomes the next crawl target. When a tie occurs, the conservative safeguard forces the faster period to prevent data loss.

Data Profiling & EDA Predictors versus target distribution and correlation

Statistical noise and hypothesis checks between collection predictors and the next crawl period (target)

EDA findings

Hypothesis 1. Product popularity: Products with a lower sales rank (higher SELL_RANK_log) and less popular categories showed markedly lower information-update frequency.

Hypothesis 2. Listing duration: Newly registered product pages are edited often, but the longer the exposure period (period increases), the more stock change rate converges to 0, a stationarity-like behavior.

Because the survival-length distribution of collected pages was multimodal and differed by change/no-change class, that feature was selected as a key variable.

Solution Architecture End-to-end crawl manager data and model pipeline

End-to-end dynamic crawling data pipeline and decision architecture

CORE FLOW

  • Hybrid branch 1 (products with enough history): When change history is sufficient (# data > 3), the product enters the Poisson \(\lambda\) stage. If many changes are detected it is handed to the ML classification model for period prediction; if no change is observed, the crawl period is extended to two days later.
  • Hybrid branch 2 (new products): Products with very little history, such as new arrivals, go to a “fixed collection every 6 hours” pipeline to secure a stable cold start and build up history.

Modeling & Optimization Classification ML and statistical model optimization

Optimizing and tuning the hybrid crawl-period classification model

Hybrid engine strategy

  • ML classification model: Predicts the next period by combining static metadata such as text (product keywords, category tags), TV shopping schedules, and exposure placement
  • Poisson statistical model: A lightweight dedicated module that closely monitors time-series stock-change patterns from live collected data

Refined evaluation metrics — To overcome the limits of plain accuracy under class imbalance, I designed a recall-centered error table and applied Cohen’s Kappa to evaluate agreement between models.

Business Impact Infrastructure savings and more accurate stock estimation

Infrastructure innovation and data value from running the smart-crawler Poisson engine (expected impact)

Infrastructure savings 5–6% reduction Suppressing redundant crawls of no-change pages cut network bandwidth and traffic cost

Data consistency Real-time error convergence Crawl resources redistributed to fast-moving popular shelves, minimizing sold-out lag time

Stability Fewer outages Optimal periods across multiple platforms avoid IP-block risk on target servers and enable a safe automated pipeline
