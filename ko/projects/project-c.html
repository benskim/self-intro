Poisson-based Adaptive Crawling Scheduler

상품별 변경 패턴을 학습해 크롤링 자원을 최적화하다

포아송 과정과 머신러닝 분류를 결합해 상품별 수집 주기를 조정하고, 실제 운영 크롤러에 적용한 예측·스케줄링 프로젝트입니다.

운영 적용 2018.12.01부터 포아송 모델과 ML 분류 모델을 운영 크롤러에 연동

시험운영 2018.08.15 종료 시험운영 뒤 실제 운영으로 전환

My Role & Contribution 역할과 기여

상품별 정보 변경 빈도를 분석하고, 포아송 모델과 머신러닝 분류 모델을 결합한 적응형 크롤링 스케줄러를 설계·구현했다. 두 모델을 실제 운영 크롤러에 연동했다.

  • 상품별 정보 변경 패턴 EDA
  • 포아송 기반 변경 발생률 추정 모델 구현
  • ML 기반 변경 여부 분류 모델 구현
  • 두 모델을 결합한 크롤링 스케줄링 로직 개발
  • 실제 운영 크롤러 연동과 적용

Problem & Data Analysis 문제와 데이터 분석

고정 주기 크롤링은 상품마다 다른 변경 빈도를 반영하지 못한다. 변경이 거의 없는 상품은 불필요하게 자주 수집하고, 재고가 빠르게 바뀌는 상품은 변경을 늦게 감지할 수 있다.

실제 상품 데이터로 다음 관계를 살폈다.

  • 상품 순위와 변경 빈도: 판매 순위가 낮은 상품일수록 정보 변경이 드물었다.
  • 노출 기간과 변경 패턴: 신규 상품은 자주 바뀌고, 노출 기간이 길어질수록 변경이 줄었다.
  • 변경 빈도 차이와 수집 주기의 적합성: 수집 페이지의 생존 길이 분포가 변경 유무에 따라 달라, 핵심 변수로 골랐다.

분석 결과로 상품별 변경 가능성에 따라 수집 주기를 차등화하는 방식을 설계했다.

Modeling & Scheduler Implementation 모델링과 스케줄러 구현

포아송 모델로 상품별 정보 변경 발생률을 추정하고, ML 분류 모델을 결합해 크롤링 우선순위와 주기를 정하는 구조를 구현했다.

\[P(N(t)=k) = \frac{(\lambda t)^k e^{-\lambda t}}{k!}\]

  • 시간 단위 관측 데이터(0.2H ~ 48H 구간별 변경 유무)로 상품별 변경 발생률 계산
  • 포아송 모델로 구간별 변경 가능성을 추정하고, 가장 높은 구간을 다음 수집 주기로 설정(같으면 더 짧은 주기를 선택)
  • ML 분류 모델로 변경 여부 예측(상품 키워드, 카테고리, 편성표, 노출 지면 등)
  • 두 모델의 결과를 결합해 크롤링 우선순위와 주기 결정
  • 신규 상품 등 관측이 부족한 경우 처리: 이력이 3건 이하인 상품은 6시간 고정 주기로 먼저 이력을 쌓음

Model Evaluation 모델 평가

실제 평가 데이터에서 모델 성능을 측정했다.

  • 변경을 놓치지 않는 것이 중요해 Recall 중심으로 변경 감지 성능을 평가
  • Cohen’s Kappa로 예측 일치도 평가
  • 상품별 변경 패턴을 반영한 적응형 스케줄링 성능 검토

Production Deployment 운영 적용

개발한 포아송 기반 스케줄링 모델과 ML 분류 모델을 실제 운영 크롤러에 연결했다.

단계 시점
시험운영 종료 2018.08.15
실제 운영 시작 2018.12.01

실제 운영 환경에서 두 모델을 연동한 적응형 크롤링을 적용했다.

Expected Operational Impact 기대 효과

운영 크롤러에 모델을 연동했고, 비용 절감·지연 단축·차단 완화는 전후 계측으로 검증할 기대 효과로 두었다.

  • 변경 가능성이 높은 상품에 크롤링 자원을 먼저 배분
  • 불필요한 반복 수집 감소
  • 품절·재고 변경 정보의 수집 지연 완화
  • 플랫폼 접근 제한 위험 완화

인프라 사용량 절감률, 품절 정보의 수집 지연, IP 차단 위험이 얼마나 개선됐는지는 전후 측정으로 확인하지 않았다.
